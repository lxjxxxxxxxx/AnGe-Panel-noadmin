## 二、工作区二进制清单（建议全部删除）

| 文件 | 大小 | 是否被流程依赖 | 结论 |
| --- | --- | --- | --- |
| `ange-panel` | 27.7MB | **不依赖**：Dockerfile L46 `go build -o ange-panel` 现场构建；release.yml 也现场构建 | 可删，AGENTS.md 的保护说法与发布流程矛盾 |
| `main` | 23.0MB | 无任何引用 | 垃圾，可删 |
| `ange-panel-new` | 23.0MB | 无任何引用 | 垃圾，可删 |

**验证过的发布链路**：
- Docker：`Dockerfile L46` 现场 `go build`，`L57` 拷贝的是镜像内构建的产物，与仓库内二进制无关
- GitHub Release：`release.yml` 现场构建 `./ange-panel`
- 安装脚本：`install.sh` 下载的是 GitHub Release asset，不读仓库内二进制

**结论**：仓库内提交的 3 个 ELF 二进制全部是多余物，删除不影响任何构建/发布/安装流程。删除后应同步更新 AGENTS.md（把 `ange-panel` 从保护名单移除，并删除"不要删除 ange-panel"的约束）。

## 三、git 历史中的二进制沉淀（141.7MB）

`git count-objects` 显示历史 pack 为 141.74 MiB，其中最大 blob 排行：

| 历史 blob | 版本数 | 说明 |
| --- | --- | --- |
| `service/sun-panel` | 6 个（各 24.9MB） | 旧目录结构时期反复提交的二进制（c03c0cc 迁移后废弃） |
| `ange-panel` | 3 个（27.7 + 24.9 + 24.9MB） | 历史版本 |
| `_tmp_move/service/sun-panel` | 1 个（24.9MB） | 临时迁移目录，工作区已删（d041932），历史仍在 |
| `_tmp_move/service/uploads/...`、`database.db` 等 | 多个 | 同上，临时目录残留 |
| `ange-panel-new` / `main` | 各 1 个（23MB） | 本次分析的新增垃圾 |

**要点**：只删除工作区文件，git 历史仍保留全部旧 blob（pack 仍约 141MB）。要彻底瘦身必须**重写历史**（如 `git filter-repo --strip-blobs-bigger-than`），这会改写全部 commit hash，需要 force push，**影响所有协作者和 fork**，属于高风险操作，必须单独确认后执行。

## 四、种子数据（`seed/uploads`，16.6MB）——需单独决策

- 内容：壁纸、图标等，被 `seed/database/database.db` 引用（验证过：数据库里有 `/uploads/2026/3/2/xxx.jpg` 的引用）
- 作用：全新安装时的默认壁纸/图标，属于产品功能数据，**不属于编译垃圾**
- 选项：
  1. **保留**（推荐）：功能需要，体积尚可接受
  2. **瘦身**：把 4MB+ 的大壁纸压缩或替换为小尺寸版本（约可减 10MB+）
  3. **删除**：全新安装将无默认壁纸，需同步改数据库引用，不推荐

---

## 五、建议执行方案（待确认）

### 方案 A：只删工作区二进制（低风险）
```bash
git rm ange-panel main ange-panel-new
# 同步更新 AGENTS.md 保护名单
```
- 释放：工作区约 73.7MB
- 历史仍 141.7MB 不变

### 方案 B：A + 重写历史彻底清除（高风险）
```bash
# 需安装 git-filter-repo
git filter-repo --strip-blobs-bigger-than 2M --force
git push --force --all
```
- 释放：仓库整体约可降到 20MB 以内（工作区 93MB → 约 18MB，历史 pack 141MB → 约 2MB）
- 代价：全部 commit hash 改变，所有克隆/fork/PR 需重新同步；**必须所有协作者确认**

### 方案 C：A + 种子瘦身
- 在 A 基础上压缩/替换 `seed/uploads` 大图，再省约 10MB
